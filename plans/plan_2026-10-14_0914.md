## Implementation steps
1. **DB** `packages/database/src/schema/tooling.ts` (export trong `index.ts`): bảng `skills`
   - Cột: `id` (text PK, uuid), `name` (text NOT NULL, unique không phân biệt hoa thường qua index `lower(name)`), `description` (text NOT NULL, mặc định `''`), `source` (enum `link|file`), `url` (text NULL), `content` (text NULL), `enabled` (boolean NOT NULL, mặc định true), `created_at`, `updated_at` (timestamp_ms).
   - CHECK: link thì có url và không có content; file thì có content và không có url.
   - Chạy `pnpm --filter @aigate/database generate` để tạo migration `0026_*`. Không sửa tay migration cũ.
2. **Domain** `tooling/domain/skill.ts` (thuần, không framework):
   - `parseSkillInput` / `parseSkillPatch`. Giới hạn: name 1–64, description ≤ 280. URL link theo đúng luật của MCP: HTTPS, HTTP chỉ cho localhost, không có user/pass trong URL, ≤ 2048. Content ≤ 256 KiB UTF-8 và không rỗng.
   - `source` không đổi được sau khi tạo.
3. **Repo** `tooling/infrastructure/skills.repo.ts`:
   - `list()` không select cột content, giới hạn `MAX_SKILLS = 200`.
   - `get(id)` trả kèm content.
   - `create`: đếm và insert trong một transaction. Vi phạm unique → 409 `SKILL_EXISTS`; vượt giới hạn → 409 `SKILL_LIMIT`.
   - `update`, `remove`, và `servable(id)` (chỉ skill file đang bật).
4. **Controllers** (đăng ký trong `toolingModule`):
   - `api/tooling/skills`, cần session: `GET` (list), `GET :id` (kèm content), `POST`, `PATCH :id`, `DELETE :id` (204).
   - `GET /v1/skills/:id/SKILL.md`, `@Public()` nhưng **luôn** đòi Bearer/x-api-key hợp lệ, kể cả khi `requireApiKey=false`. Lỗi: 401 `INVALID_API_KEY`; 404 nếu không có, đang tắt, hoặc là skill dạng link. Header trả về: `text/markdown; charset=utf-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
5. **Web API** `features/integrations/api.ts`: các hook `useSkills`, `useSkill(id)`, `useCreateSkill`, `useUpdateSkill`, `useDeleteSkill` (invalidate theo mẫu MCP).
6. **UI** `Skills()` viết lại:
   - **Xóa mảng gán cứng**, xóa cảnh báo về 9router.
   - Bảng gồm: tên, mô tả, nguồn (Link/File), trạng thái, URL copy (link thì URL gốc; file thì `${origin}/v1/skills/<id>/SKILL.md`), các nút Bật/Tắt, Sửa, Xem, Xóa.
   - Modal tạo/sửa có 2 tab nguồn: Link (ô URL) và File (`<input type=file accept=".md,text/markdown">`). Kiểm tra kích thước phía client. Tự điền name/description từ frontmatter YAML nếu có (helper thuần).
   - Xem nội dung bằng `<pre>` dạng text, không render HTML, để tránh XSS.
   - Ghi chú cho skill file: agent cần gửi `Authorization: Bearer $AIGATE_KEY`. Không bao giờ chèn key thật.
   - Đủ trạng thái loading, empty, lỗi đọc (code + Retry), mutation đang chạy không bấm lặp được, lỗi thì giữ nguyên bản nháp.
