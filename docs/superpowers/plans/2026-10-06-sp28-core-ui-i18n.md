# SP28 Core Dashboard Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize the existing shell, Auth, Settings, Overview and shared UI guidance into EN/VI without changing gateway behavior.

**Architecture:** Two static JSON catalogs and one pure translation/Intl module feed a single React locale provider above the existing application providers. Existing queries, router, SSE and business identifiers retain their identities. Raw errors and localized message inputs are resolved when rendered, not frozen into translated component state.

**Tech Stack:** Existing React 19, TypeScript 5.9, Vite 7, TanStack Query/Router, Radix UI, native Intl and node:test. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-06-sp28-core-ui-i18n-design.md` — approved on 2026-10-06. Native implementation/targeted checks and the subsequently authorized isolated browser acceptance pass (2026-10-08). Checklist below records the original planned steps; the completion handoff is the permanent execution evidence.

## Global Constraints

- Language is exactly `en` or `vi`.
- Store only this enum under `aigate-language`; do not include it in the SP27 server settings document.
- Use `en-US` for English and `vi-VN` for Vietnamese through native `Intl`.
- Keep costs in USD: no currency conversion, rate lookup or VND relabeling.
- The confirmation token `IMPORT` remains literal ASCII; only the instruction around it is translated.
- Preserve API URLs, query keys, request bodies, IDs, provider/model names, gateway URLs, environment variable names, filenames and error codes.
- Preserve raw validation messages, provider diagnostics and Overview's server `attention.message`.
- Keep the current single-toast capacity and six-second dismissal lifecycle; changing locale must not restart the timer or add a queue.
- No server locale endpoint, schema/migration, dependency, third-party translation request, remote language pack, DOM scanner or unrelated refactor.
- No locale in query keys or stream-effect dependencies; no refetch, stream reopening, mutation replay or form/review reset from selection.
- Other feature-specific pages remain English; do not claim whole-dashboard localization.
- Apply patches only to intended files; preserve concurrent user changes. Normal scoped git checkpoints are allowed; stop and report an actual write refusal without permission workarounds.
- Test/browser commands below are proposed execution steps, not results. Run them only after the user authorizes targeted verification; otherwise keep acceptance explicitly unverified. Never run the broad `pnpm test` suite for this slice.

## Review Focus

1. Storage getter/setter denial: locale fallback must work even when the existing theme/developer storage accesses would otherwise crash Shell. Task 2 pins this with a real blocked-storage browser case.
2. Prototype-looking keys and literal markup/dollar/braces in parameters: interpolation must not resolve inherited properties, evaluate content or rescan substituted values. Task 1 exercises these inputs.
3. An already-visible error with numeric context and a raw provider diagnostic: switching language changes only owned advice, not its code/detail. Task 3 tests resolution and its browser probe.
4. Translated tab labels/search and a pending import: labels cannot become business keys; switch preserves active tab, values, selected document and reviewed fingerprint. Task 4 tests the actual controls.
5. Existing SSE and toast deadlines: switch must not reconnect a live/stopped stream or extend a six-second toast. Tasks 3/5 compare activity and controlled time with a temporary browser harness.

```ts
import en from "./locales/en.json" with { type: "json" };
import vi from "./locales/vi.json" with { type: "json" };

export const normalizeLanguage = (value: unknown): Language => value === "vi" ? "vi" : "en";
export function readLanguage(read: () => string | null): Language {
  try { return normalizeLanguage(read()); } catch { return "en"; }
}
export function persistLanguage(language: Language, write: (value: Language) => void): boolean {
  try { write(language); return true; } catch { return false; }
}
export function interpolate(template: string, params: Params = {}): string {
  return template.replace(/\{([a-zA-Z][a-zA-Z0-9_]*)\}/g,
    (marker, name: string) => Object.hasOwn(params, name) ? String(params[name]) : marker);
}
export function lookupMessage(language: Language, key: string,
  catalogs: Readonly<Record<Language, Readonly<Record<string, string>>>>): string {
  if (Object.hasOwn(catalogs[language], key)) return catalogs[language][key];
  return Object.hasOwn(catalogs.en, key) ? catalogs.en[key] : key;
}
export function translate(language: Language, key: MessageKey, params?: Params): string {
  return interpolate(lookupMessage(language, key, { en, vi }), params);
}
```
