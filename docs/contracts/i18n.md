# Core dashboard localization — SP28

EN/VI is browser presentation only: two static JSON catalogs, one React locale
provider, native Intl and localStorage `aigate-language`. Missing/invalid
preferences fall back to en; denied storage leaves selection usable in memory.
`html lang` follows the preference, including standalone Auth. No locale API,
database field, export key, dependency, network translation or cross-tab sync.

Scope: shell/navigation/search; login/welcome/callback; General/Auth/Developer;
Overview; owned shared defaults/errors/core notices. SP32 extends owned copy on
Media Providers and Voice Browser (`media-dashboard.md`, `speech.md`); other
feature pages and raw server/provider diagnostics remain English/verbatim. Preserve URLs, query
keys, model/provider IDs/names, error codes, environment names and filenames.
`IMPORT` stays literal. Settings export still carries its 16 server keys.

Catalog keys/placeholders must match. Missing VI text falls back to English;
unknown keys/missing parameters remain visible markers, never undefined or HTML.
Interpolation is one pass over the fixed template, with own-property lookup.
Only supported wire-code advice lives under `errors.*`; internal formatting
variants/fallbacks use `errorAdvice.*`, so unknown API codes cannot select them.

Format with en-US/vi-VN, preserve USD, precision and the usage timezone. Language
changes do not recreate router/query providers, refetch, reopen SSE, reset
form/tab/import state, replay mutations or restart toast dismissal. Inline
errors and localized notices retain inputs for render-time resolution; legacy
string notices remain supported. One toast, existing six-second lifetime.

Spec/plan: `docs/superpowers/specs/2026-10-06-sp28-core-ui-i18n-design.md` and
`docs/superpowers/plans/2026-10-06-sp28-core-ui-i18n.md`. Native locale/errors/SSE
checks verify catalog, formatting, diagnostics, real component rendering and
existing stream-reader boundaries. Isolated browser acceptance passed on
2026-10-08: storage denial, state/payload preservation, toast/SSE lifetimes,
raw diagnostics and EN/VI layout at 1440/929/390px. See the handoff for actual
mock boundaries and evidence. This is core-scope acceptance, not whole-dashboard
localization, baseline visual regression or full accessibility/performance certification.

SP32 follows the same `LocaleProvider` and static catalogs. Media kind labels,
route/account status, voice controls, empty/error/help text, gender labels and
language/region display names use the selected EN/VI locale. Provider/model/
voice IDs and names, endpoint paths, error codes, raw diagnostics and the
fixed English preview sample remain literal. A locale switch renders text
without changing voice query keys, filters, selected model/provider, preview
payload or playback. Copy/preview toasts resolve at render time. The existing
200-row voice limit, user-triggered preview, abort and object-URL cleanup stay
in force. SP32 adds no server API, dependency or storage key.
