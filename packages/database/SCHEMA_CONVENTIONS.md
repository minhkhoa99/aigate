# AIGate schema conventions

Each bounded context adds its own tables in the SP that implements it, after its Feature Matrix entries are labeled and its contract is defined. Follow `porting-behavior-not-code`. These rules apply to every context. Each one cites the matrix entries (`docs/discovery/feature-matrix/`) that justify it. Change a rule here, not in one table.

## Where things live

- Put each context's table definitions in `packages/database/src/schema/<context>.ts`.
- Generate migrations with `drizzle-kit` into `packages/database/drizzle/`. Do not edit a migration that has shipped; add a new one.
- Put repositories in `apps/server/src/modules/<context>/infrastructure/*repo*.ts`. The `aigate/bounded-query` lint rule only checks files matching that path.
- Settings, API keys, and pricing get only a Drizzle repository class, with no use-case wrapper (spec §4.2).

## Shape

1. **Use typed columns for anything queried, filtered, or updated on its own.** JSON columns are only for opaque payloads that are read and written whole. Do not use a generic key-value table. 9router kept tokens, expiries, and `modelLock_*` keys in an unchecked `data` blob, where a mistyped key silently became a new key. Account locks become their own table, keyed by `(accountId, modelId | NULL)`, with a `reason` and an `until` column (spec §4.1).
   - Evidence: `connection.storage-shape-json-blob`, `account.lock-storage-persistence`, `proxypool.storage-json-blob`, `connection.provider-node-repo-storage`.
2. **Store instants as integer UTC epoch milliseconds** (`integer(..., { mode: "timestamp_ms" })`). Compare them numerically. Compute day buckets from an explicit, configured timezone, never from the server's local zone. Normalize alternative input spellings at the boundary.
   - Evidence: `account.select-all-unavailable-response` (ISO strings compared with a string sort), `usage.daily-rollup-aggregation` (local-time `dateKey`), `oauth.grok-cli-bulk-import`.
3. **Booleans are `integer(..., { mode: "boolean" })`, `NOT NULL`, with an explicit default.** Never infer them from "anything but `false`".
   - Evidence: `connection.storage-shape-json-blob`, `proxypool.storage-json-blob`.
4. **IDs are opaque text primary keys generated by the application** (`crypto.randomUUID()`), unless the domain has a real natural key. Ordering fields such as `priority` are data, never identity.
   - Evidence: `connection.delete-and-reorder`.
5. **Each recorded event gets its own row ID.** Do not deduplicate on its content.
   - Evidence: `usage.history-write-dedup-transaction` (`SUSPECTED_BUG`: identical requests in the same millisecond were dropped).

## Integrity

6. **Declare uniqueness in the database and map constraint violations to 409 or 400.** Never check with a `SELECT` first, and never let a create silently upsert over an existing row. Foreign keys are on for every driver; declare `ON DELETE` explicitly.
   - Evidence: `combo.storage-shape`, `combo.api-crud`, `proxypool.storage-json-blob`, `catalog.alias-dual-convention-collision`.
7. **Do every read-merge-write in one transaction, and keep transactions short.** The driver chain serializes all access through one lock, so never await network I/O inside a transaction. Token refresh is single-flight per connection, outside any transaction.
   - Evidence: `connection.update-atomic-merge-and-reorder`, `pricing.crud-api`, `catalog.model-disabled-crud-api`, `account.concurrent-refresh-race` (`SUSPECTED_BUG`), SPIKE-1.
8. **Use versioned migrations; never rename a key silently.** A renamed setting or column must carry the old value forward in its migration.
   - Evidence: `settings.defaults-and-merge`.

## Secrets

9. **Never store secrets in plaintext.**
   - Store API keys as a hash and show them only once, when issued. The key format is decided in SP6 (spec §13).
   - Encrypt OAuth tokens and the sudo secret through `SecretCipherPort`.
   - Hash passwords.
   - Strip or mask secrets on every read, and exclude them from mass assignment.
   - Treat an export as a credential bundle.
   - Evidence: `apikey.list-keys` (`SUSPECTED_BUG`), `apikey.generate-key`, `settings.get-secret-stripping`, `settings.patch-protected-keys`, `settings.database-export-import`, `connection.storage-shape-json-blob`, spec §4.2.

## Growth and hot paths

10. **Give every growing table a named retention limit and a pruning path.** Delete expired locks by their `until` time, not only when a later request succeeds.
    - Evidence: `usage.request-details-buffered-persistence`, `account.lock-storage-persistence`, `account.clear-error-on-success`.
    - No entry defines retention for usage history or daily rollups. Decide that when the `usage` context lands.
11. **Keep per-request writes off the hot path through a bounded buffered writer.** It flushes on an interval or when a batch fills, in one transaction. It drops the oldest entries when full, and counts both drops and write failures. Cache hot-path reads and invalidate them on write. Record billed usage even when a stream aborts.
    - Evidence: `usage.write-not-synchronous` (fire-and-forget; errors swallowed), `usage.request-details-buffered-persistence`, `settings.hot-path-read-no-cache`, `routing.usage-recording-timing` (`SUSPECTED_BUG`), spec §6.1.
12. **Write files atomically:** write a temp file, then rename. The sql.js driver already does this.
    - Evidence: `clitools.write-not-atomic` (`SUSPECTED_BUG`).
